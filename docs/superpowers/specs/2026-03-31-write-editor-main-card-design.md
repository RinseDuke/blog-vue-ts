# Write 主编辑卡材质统一设计

## 目标

- 将 `write` 页的标题区和正文编辑区合并为一张主编辑卡，消除标题区与正文画布分离带来的割裂感。
- 保持工具栏位于主编辑卡上方，继续作为独立控制层，但在材质、边界、阴影和间距上与主编辑卡属于同一套系统。
- 让浅色 / 深色模式下的层级过渡更平滑，尤其是深色模式尽量接近 GitHub Dark 的柔和分层，而不是大块硬切。

## 当前问题

- 标题输入框直接贴在页面主容器里，实时编辑器 / 源码编辑器 / 阅读视图又是另一层内容区域，标题与正文不像同一块写作画布。
- 工具栏、标题区、正文区、发布设置虽然都已逐步卡片化，但主写作区仍缺少一个明确的“主表面”，层级不够稳定。
- `source` 模式下的原生文本域背景和 `live` / `read` 模式的内容背景不一致，深色模式更容易出现色块割裂。

## 方案对比

### 方案 1：标题区 + 正文区合并为一张主编辑卡，工具栏保留在卡片上方

- 工具栏继续独立 sticky，避免和正文滚动逻辑耦合。
- 标题区作为主卡片头部，正文三种模式共用同一个内容画布容器。
- 通过弱分隔线、统一圆角、统一内阴影和共享 token，让标题与正文成为连续材质。

这是本次采用方案。改动集中、维护成本最低，也最符合你要求的“统一材质层级 + 平滑边界过渡”。

### 方案 2：把工具栏也吸附进主编辑卡内部

- 一体化更强。
- 但 sticky 行为、模式切换和移动端换行会更复杂，卡片顶部也更容易显得拥挤。

### 方案 3：标题区保持独立，只调整边框与背景

- 改动最小。
- 但只能缓和割裂，不能真正建立统一的主写作表面。

## 设计决策

### 1. 新增统一主编辑卡

- 在 `src/views/Write.vue` 中引入 `editor-main-card` 结构。
- 卡片内部拆分为：
  - `editor-main-card__header`：承载标题输入。
  - `editor-main-card__canvas`：承载 `live` / `source` / `read` 三种正文模式。
- 通过单一卡片边框、共享背景和轻分隔线，确保标题与正文属于同一材质表面。

### 2. 工具栏放在主编辑卡上方，但保持同一材质语言

- `EditorToolbar` 不进入卡片内部，避免 sticky 与正文布局互相影响。
- 工具栏和主编辑卡之间保留明确但不突兀的垂直间距。
- 视觉上复用 write 页已有 surface token，并补足主编辑卡专用 token，让两者属于同一个层级系统。

### 3. 三种正文模式共用同一画布容器

- `live`、`source`、`read` 统一挂在 `editor-main-card__canvas` 内。
- `source` 模式不再使用明显跳出的独立背景块，而是改为融入主卡片的内层画布。
- `read` 空状态也使用同一画布和同一层级，不再像额外插入的占位块。

### 4. 深色模式继续向 GitHub Dark 靠拢

- 主编辑卡主体采用较接近 `#161b22` / `#0d1117` 的明暗关系。
- 分隔线、内层画布和 hover / focus 态避免偏蓝过重，强调柔和、稳定和低噪声。
- 标题区与正文区的分层主要通过亮度差和弱边框完成，而不是大对比块面。
