# 移动端文章筛选折叠设计

## 目标

- 减少文章列表页在移动端首屏中筛选区占用的高度。
- 保留现有筛选能力：排序、每页显示、发布时间、自定义日期。
- 不改变桌面端布局，不改变筛选逻辑、URL 同步和下拉控件数据结构。

## 非目标

- 不改桌面端侧边筛选的视觉结构。
- 不改 `ArticleListView.vue` 中的筛选计算、分页、排序和 query 同步逻辑。
- 不把移动端筛选改成抽屉、全屏层或多级分组流程。

## 当前情况

- `src/components/post/ArticleFilters.vue` 当前在桌面和移动端都直接渲染完整筛选内容。
- 在移动端窄屏下，完整筛选卡片会占据较大垂直空间，影响文章列表内容的首屏可见性。
- 当前组件已经有完整的筛选字段和重置逻辑，问题主要是移动端呈现方式，而不是功能缺失。

## 方案对比

### 方案 1：移动端单按钮折叠整块筛选区

- 移动端顶部显示一行控制条：`筛选` 按钮 + `重置` 按钮。
- 点击 `筛选` 后，以当前卡片内部的下拉方式展开或收起完整筛选表单。
- 桌面端继续保持现状。

这是本次采用方案。改动最小，复用现有筛选内容最多，也最符合“减少空间占用但不改逻辑”的目标。

### 方案 2：移动端改为抽屉或全屏筛选层

- 将筛选内容移入弹层。

虽然节省空间更多，但会改变交互路径，也更容易影响现有页面逻辑和层级关系，不适合这次最小优化。

### 方案 3：每个筛选项独立折叠

- 把排序、每页显示、发布时间拆成三块按钮后分别展开。

这种方式会增加点击次数，也会让移动端筛选区更碎，整体不如一个总开关清晰。

## 设计决策

### 1. 只在移动端折叠

- 通过 `ArticleFilters.vue` 内部状态控制移动端展开/收起。
- 桌面端继续默认展开，不改变当前侧边筛选卡片的使用方式。

### 2. 保留现有内容结构

- 展开后的筛选表单继续复用现有 `DropdownSelect`、`DatePickerInput` 和分组顺序。
- 不重写字段，不迁移到新的组件结构，不改 emit 和 v-model 接口。

### 3. 控制条轻量化

- 移动端筛选卡片顶部只显示一个主按钮用于展开/收起。
- `重置` 按钮继续保留，但只作为辅助操作存在。
- 可以在按钮文案或状态中体现当前是“展开”还是“收起”，但不引入复杂动画和额外状态摘要。

### 4. 交互保持连续

- 筛选面板展开后仍在原位置内联显示，不跳转、不遮罩、不打断滚动上下文。
- 自定义日期区域继续跟随“发布时间”筛选项显示，不做额外分层。
