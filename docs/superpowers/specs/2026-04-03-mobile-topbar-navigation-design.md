# 移动端顶部导航优化设计

## 目标

- 为移动端提供独立于桌面端的顶部导航体验，避免把桌面端的完整搜索框和完整导航按钮直接压缩到小屏幕里。
- 保持桌面端现有信息架构基本不变，仅对移动端做针对性优化。
- 降低首页首屏顶部占高，让用户进入移动端时更快看到正文内容。
- 保持浅色 / 深色模式材质连续，避免顶部栏、搜索层和页面主体出现 UI 割裂。

## 当前问题

- `src/App.vue` 当前把 `TopBrand`、`TopSearchBox`、`TopNavigation`、`TopThemeToggle` 统一放在一个顶部容器中，移动端只是简单换行。
- `src/components/navigation/TopHeaderLayout.vue` 在移动端只做 `flex-wrap`，没有真正区分移动端的布局和交互。
- `src/components/search/TopSearchBox.vue` 在移动端仍常驻完整搜索输入框，和导航一起占据了过多垂直空间。
- `src/components/navigation/TopNavigation.vue` 在移动端仍然使用桌面端同类按钮组，只是允许横向滚动，视觉上仍然偏厚重。

## 方案对比

### 方案 A：紧凑顶部栏 + 搜索触发式浮层 + 轻量导航条

- 移动端顶部第一行只保留品牌、主题切换和搜索触发按钮。
- 搜索框不再默认展开，点击后再打开移动端搜索层。
- 主导航继续保留在顶部，但改成更轻、更矮、更适合手指点击的标签式导航条。
- 桌面端仍沿用现有布局与交互。

这是本次采用的方案。改动范围可控，不改变整站导航模型，同时能直接解决顶部过高的问题。

### 方案 B：紧凑顶部栏 + 搜索按钮 + 菜单抽屉

- 导航整体收入菜单抽屉。
- 顶部只保留品牌和操作按钮。

优点是最省空间，但内容站高频切换首页、文章、写作和个人中心时会增加一步操作，不适合当前博客站点。

### 方案 C：顶部操作栏 + 底部 Tab 导航

- 顶部只保留品牌和操作。
- 主导航迁移到底部固定栏。

这是更激进的移动端方案，长期体验可能更强，但会扩大改动范围，涉及安全区、页面底部层级和更多页面回归，不适合作为当前这轮优化。

## 设计决策

### 1. 顶部栏拆成“桌面端布局”和“移动端布局”

- 桌面端保持现有 `Brand + Search + Navigation + ThemeToggle` 的信息结构。
- 移动端改成独立布局：
  - 第一行：`Brand + ThemeToggle + SearchTrigger`
  - 第二行：`MobileTopTabs`
- 仍复用同一组路由能力和搜索数据源，避免业务逻辑分叉。

### 2. 移动端搜索改成触发式而不是常驻式

- 默认只显示搜索图标按钮，不显示完整输入框。
- 点击后打开覆盖在顶部内容上的搜索层，内部复用现有搜索输入、搜索建议、搜索历史和推荐文章。
- 搜索层关闭后回到原始顶部结构，不占额外首屏高度。
- 搜索层材质沿用站点现有玻璃层与边界色，保持和顶部栏、页面主体一致。

### 3. 移动端导航改成更轻的标签式导航

- 不再沿用桌面端厚按钮容器。
- 移动端导航使用更低高度、更紧凑 padding、更明确的 active 状态。
- 导航仍保留四个入口：`首页`、`文章`、`写作`、`个人中心 / 登录`。
- 如果空间不足，优先压缩内部间距和字号，而不是继续堆高顶部容器。

### 4. 统一顶部材质与滚动边界

- `TopHeaderLayout` 继续作为顶部材质壳层，但在移动端改用更紧凑的圆角、间距和内边距。
- 搜索层和导航条需要继承相同的表面色、描边色和阴影逻辑，避免出现“顶部是一套材质、弹层又是一套材质”的割裂感。
- `App.vue` 中的 `padding-top` 需要按移动端新高度重算，避免首屏空白过大或内容被盖住。

### 5. 行为保持可预测

- 桌面端搜索仍然保持当前常驻输入框体验。
- 移动端打开搜索层时，不引入额外路由状态；使用组件内部状态控制开合，避免页面切换时状态残留。
- 路由切换时自动关闭移动端搜索层，避免切页后顶部状态错乱。

## 组件边界

- `src/App.vue`
  - 负责根据视口组织桌面端 / 移动端顶部结构和搜索开合状态。
- `src/components/navigation/TopHeaderLayout.vue`
  - 负责顶部统一材质壳层，不承担复杂业务逻辑。
- `src/components/search/TopSearchBox.vue`
  - 继续承载桌面端搜索输入；移动端模式下可复用其输入和下拉内容能力。
- `src/components/navigation/TopNavigation.vue`
  - 保留桌面端导航。
- 新增移动端组件：
  - `src/components/navigation/MobileTopTabs.vue`
  - `src/components/search/MobileSearchSheet.vue`

## 数据与交互流

1. 页面加载时，桌面端直接显示完整搜索框；移动端仅显示搜索按钮。
2. 用户在移动端点击搜索按钮。
3. `App.vue` 更新移动端搜索开合状态。
4. `MobileSearchSheet` 打开，展示输入框、搜索建议、历史和推荐内容。
5. 用户提交搜索后沿用现有 `handleSearch`，跳转到 `/search?q=...`。
6. 路由变化时自动关闭移动端搜索层。

## 风险与控制

- 风险：移动端顶部重构后可能影响写作页滚动隐藏逻辑。
  - 控制：保持 `isNavHidden` 仍挂在统一顶部容器上，只调整内部布局，不改隐藏判定逻辑。
- 风险：搜索层与现有下拉逻辑重叠，导致焦点或展开状态冲突。
  - 控制：移动端搜索层使用独立开合状态，不直接复用桌面端输入框的常驻展示方式。
- 风险：桌面端被意外影响。
  - 控制：样式尽量用移动端断点隔离，桌面端组件结构尽量不动。
