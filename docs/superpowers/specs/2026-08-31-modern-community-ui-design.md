# 现代社区化 UI 设计

## 目标

在保留个人博客内容与作者辨识度的同时，将全站升级为结构成熟的社区论坛。信息架构参考 Discourse，但视觉不直接复刻：使用接近 Apple 系统字体的现代排版、克制的中性色和清晰的内容层级。

## 已确认的产品约定

- 博客文章与社区帖子使用同一套主题模型、同一条主题信息流和同一套详情页结构。
- 普通登录用户可以发帖，所有帖子发布后立即公开，不设置发布前审核。
- 个人博客内容通过“官方”标识、优先级和标题层级区分，不单独建立另一套页面风格。
- 首页与主题列表不使用大图或头图；图片只出现在文章正文中。
- 桌面端采用固定顶栏、左侧导航、中间内容、右侧上下文栏；移动端左侧导航进入抽屉，右栏内容移动到主内容下方。
- 登录、注册和编辑器保留顶栏，隐藏左右侧栏，使用更宽的专注布局。

## 视觉方向

### 字体与排版

- 全站使用系统无衬线字体。中文优先使用苹方，英文在 Apple 设备上自然使用 SF Pro，其他平台使用相近的系统字体回退。
- 官方文章不再使用独立衬线字体，仅通过字号、字重、间距和标识建立层级。
- 文章正文最大宽度约 720px，行距偏舒展；主题列表与回复区域使用更紧凑的行高。
- 桌面端主题列表每屏约显示 8～10 条，兼顾浏览效率和阅读舒适度。

### 色彩与表面

- 浅色主题使用纯净白、浅雾灰和柔和黑；深色主题使用接近系统深色界面的中性背景。
- 蓝色只用于链接、选中状态、焦点和主要操作，不大面积铺设品牌色。
- 不使用液态玻璃、背景模糊、彩色光球、报纸纹理或厚重阴影。
- 页面以底色、白色内容区和细分隔线组织层级。主题列表使用连续行，不堆叠卡片；侧栏摘要、作者信息和弹窗可以使用轻圆角容器。

## 全站信息架构

### 顶栏

- 保留站点标识、全局搜索、发帖入口、通知和用户菜单。
- 顶栏固定在页面顶部，视觉高度保持克制；移动端只保留核心操作。

### 左侧导航

- 提供首页、最新、未读、分类、标签、收藏和个人内容等稳定入口。
- 当前页面使用背景与文字权重共同标识，不能只依赖颜色。

### 中间内容区

- 首页默认展示统一主题流，支持最新、热门、未读等排序或筛选。
- 官方博客和社区帖子混排；官方内容允许置顶或提高排序优先级，但不使用大图强化。
- 主题详情页中，首帖就是完整文章，后续回复按时间连续排列。

### 右侧上下文栏

- 首页显示社区简介、热门标签和活跃讨论。
- 文章页显示目录、作者信息、阅读进度和相关主题。
- 只显示与当前页面有关的信息，避免长期固定的无关模块。

## 核心组件

### 主题列表行

每行包含头像、标题、分类或标签、一行摘要、作者、更新时间，以及回复数、浏览量和最近活动。官方内容增加低调的“官方”标识。移动端保留标题、关键状态和更新时间，次要统计按优先级隐藏。

### 主题详情与回复

- 首帖采用文章阅读排版，后续回复使用更紧凑的讨论排版。
- 桌面端作者信息位于内容左侧，正文下方统一放置点赞、收藏、分享和回复操作。
- 右侧栏在长文章中显示目录与阅读进度；标题较少时不显示空目录。

### 发帖编辑器

- 桌面端从页面底部展开，可以边查看主题边写作；移动端切换为全屏。
- 保留现有草稿自动保存能力，标题与正文通过校验后可直接发布。
- 发布成功后进入新主题；发布失败时保留草稿和当前输入，允许重试。

## 数据流与状态

现有文章数据继续通过 postService 和帖子状态仓库读取。界面层增加统一的主题视图模型，将博客字段映射为列表与详情页需要的标题、作者、分类、活动时间、回复数、浏览量和官方状态。组件不直接读取后端原始响应。

```
页面视图
  → 主题列表、详情、回复与编辑器组件
  → 帖子和评论状态仓库
  → postService、commentService
  → 后端接口或现有本地模拟数据
```

官方优先级属于排序与展示元数据，不复制文章内容。现有博客接口暂时没有的统计字段使用明确的默认值或隐藏处理，不能伪造数据。后端能力扩展时保持视图模型稳定。

## 响应式规则

- 桌面端：固定顶栏，左中右三栏；文章正文保持约 720px 的可读宽度。
- 平板端：优先收起右侧栏，保留左侧导航与主体内容。
- 移动端：左侧导航改为抽屉，右侧信息移到内容下方；统计列精简，编辑器全屏。
- 登录、注册与写作页在所有尺寸下都使用专注布局，不渲染侧栏。

## 加载、错误与空状态

- 列表和详情加载使用与最终结构一致的简洁骨架屏，避免页面跳动。
- 空主题流提供清楚的发帖入口；空回复区提示用户参与讨论。
- 发布期间禁用重复提交并显示提交状态；失败后恢复操作，同时保留本地草稿。
- 请求失败使用页面内提示或轻量通知，不用空白页面替代已有内容。
- 图片加载失败不得破坏正文宽度和布局。

## 可访问性

- 浅色与深色主题都满足文字、边框、焦点状态的可辨识度要求。
- 导航、主题列表、弹窗和编辑器支持键盘操作，并提供清晰焦点状态。
- 选中、未读、警告等状态不能只依赖颜色表达。
- 动画保持轻量，并尊重系统的减少动态效果设置。

## 测试与验收

- 单元测试覆盖主题视图模型、排序优先级、移动端字段裁剪、发布成功和失败状态。
- 组件测试覆盖主题列表行、官方标识、侧栏条件渲染、编辑器开合与草稿保留。
- 浏览器验证覆盖首页、主题详情、发帖、登录和个人页面，并检查桌面、平板、手机三档布局。
- 浅色与深色主题都进行关键页面截图对比。
- 完成后运行类型检查、现有测试、代码规范检查和生产构建。

## 边界

- 本轮不引入发布前审核流程，不改变“所有帖子直接发布”的约定。
- 本轮不通过大图、轮播图或营销式首屏突出官方文章。
- 不引入新的大型界面组件库，也不复制 Apple 或 Discourse 的品牌资源。
- 不在界面改造中硬编码后端尚未提供的社区统计数据。

## 实施顺序

1. 建立全站字体、颜色、间距、边框和响应式令牌。
2. 重构顶栏、左侧导航、页面框架和移动端抽屉。
3. 将首页与文章列表统一为主题信息流。
4. 重构主题详情、回复区域和右侧上下文栏。
5. 将现有写作页适配为桌面底部编辑器与移动全屏编辑器。
6. 统一登录、注册、个人页面和通用状态组件。
7. 补齐测试、截图验证和生产构建检查。
