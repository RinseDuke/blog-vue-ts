# Mock 示例文章正文清理设计

## 目标

- 清理 `mock` 示例文章中不适合上线展示的正文内容。
- 避免文章详情页继续展示 `Mock`、`后端切换`、`接口调试` 一类示例说明。
- 保持现有文章数据结构稳定，不影响列表、详情、筛选和 mock 发文链路。

## 非目标

- 不修改 UI。
- 不修改服务层。
- 不修改路由。
- 不重做 mock 数据生成方式。

## 当前情况

- `src/mocks/posts.ts` 中的 `buildArticleContent()` 会为所有文章统一追加两段说明性文案，这些文案明显偏测试和接后端场景。
- 少数文章 seed 自身的标题、摘要、导语和小节也直接围绕 `Mock / API / 后端` 展开。
- 这些内容会在文章详情页直接展示，和准备上线的内容气质不一致。

## 方案对比

### 方案 1：只在 `src/mocks/posts.ts` 中做定向内容清理

- 删除通用正文模板中的测试说明和后端切换说明。
- 将少数不适合展示的文章内容改写为普通博客主题。
- 保持文章数量、字段结构、作者、时间、封面、标签和现有数据入口不变。

这是本次推荐方案。改动面最小，风险最低，也最符合“只处理展示内容”的目标。

### 方案 2：只删通用模板文案

- 只处理 `buildArticleContent()`。
- 不改具体文章 seed。

优点是改动更小，但无法彻底解决问题，因为部分文章本身仍会展示 `Mock / API / 后端` 主题内容。

### 方案 3：全量重写所有 mock 文章

- 统一重写全部标题、摘要和正文主题。

一致性最好，但明显超出当前需求，回归成本也更高。

## 设计决策

### 1. 修改范围限定在 `src/mocks/posts.ts`

- 不触碰 `src/services/postService.ts`、视图层和路由层。
- 继续沿用现有 `mockPosts` 导出方式，避免影响消费方。

### 2. 保持数据结构稳定

- 保持 `id`、`slug`、`publishedAt`、`author`、`coverImage`、`tags`、`featured` 等字段结构不变。
- 改动聚焦在 `title`、`excerpt`、`contentLead`、`contentSections` 以及通用正文模板。

### 3. 清理策略分两层

- 第一层：移除 `buildArticleContent()` 中统一附带的测试/切换说明。
- 第二层：定向替换少数以 `Mock / API / 后端` 为主题的文章展示文案，使其变成正常博客内容。

### 4. 回归保护

- 增加一个针对 mock 文章内容的回归测试，防止后续再次引入不适合上线展示的关键词或模板文案。
- 测试重点放在最终导出的 `mockPosts` 展示内容，而不是只检查原始 seed。

## 数据与行为影响

- 文章列表数量不变。
- 文章详情页仍按现有 `id` / `slug` 链路读取。
- mock 发文、本地持久化、搜索筛选、推荐和排序逻辑都不需要改动。
- 唯一变化是示例文章的展示文案更接近真实博客内容。

## 测试与验证

- 先补充 mock 内容回归测试，锁定不应再出现的展示文案。
- 运行 `npm run test:run`。
- 运行 `npm run type-check`。
- 运行项目的运行态验证命令，确认文章展示链路正常。
- 做视觉回归，至少检查文章详情页：
  - 浅色模式
  - 深色模式
  - 桌面宽度
  - 移动宽度
