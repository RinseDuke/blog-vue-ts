# Write Slim Focus Toolbar 设计

## 目标

- 将 `write` 页进一步收敛为“主内容优先”的写作界面，让标题和正文成为页面绝对主角。
- 保留现有工具区、主编辑区、发布设置、底部状态栏的大结构，不做破坏式重排。
- 把当前两行工具栏压缩为一行紧凑工具栏，减少纵向占用，同时保留高频格式能力。
- 统一工具栏、主编辑卡、发布设置、状态栏的材质语言、间距节奏和控件密度，让页面看起来属于同一套编辑系统。
- 保证桌面端与移动端都不会回退为两行工具栏，并尽量把垂直空间还给正文。

## 当前问题

- 工具栏当前由多组较厚的按钮卡片组成，并且会占据两行，导致编辑器上方的控制层视觉重量过高。
- 标题区和正文区已经具备主编辑卡雏形，但在工具栏强存在感的对比下，第一视觉中心仍然不够稳定。
- 发布设置和底部状态栏都使用较强的卡片化表达，叠加后让页面存在多个竞争主区域，缺少明确的主次。
- 当前 write 页虽然已经有统一 token，但工具栏、主编辑卡、发布设置、状态栏的控件密度和装饰强度还不够一致。
- 移动端如果继续依赖换行承载工具按钮，会挤压正文首屏空间，违背“专注写作”的目标。

## 方案对比

### 方案 A：Slim Focus

- 保留当前总体结构。
- 将工具栏重构为单行紧凑工作带，常用操作常驻，低频操作收进“更多”菜单。
- 继续让标题区和正文区作为主编辑卡主体，其他控制区统一降噪。

这是本次采用方案。它最符合“更专注写作”和“保留工具但减少占用”这两个已确认约束，同时改动范围可控。

### 方案 B：Ultra Quiet

- 进一步弱化工具栏，只保留图标或极少文字。
- 页面会更安静，但可发现性和易用性会下降，尤其对首次使用者不友好。

### 方案 C：Editorial Desk

- 保留单行工具栏，但强化创作工作台气质和装饰感。
- 视觉记忆点更强，但会重新抬高工具层存在感，不符合本次“主内容优先”的方向。

## 已确认设计

### 1. 布局与层级

- `WritePage` 保留当前大结构：
  - 顶部导航
  - 单行紧凑工具栏
  - 主编辑卡片
  - 下方发布设置
  - 底部状态栏
- 标题输入和正文编辑区继续作为第一视觉中心。
- 工具栏缩成一条更轻、更薄的操作层，不再通过双层卡片阵列抢占主视线。
- 发布设置继续留在页面下方，不改成右侧窄栏或悬浮侧栏。
- 状态栏继续固定底部，但会在材质和按钮密度上与工具栏统一。

### 2. 工具栏内容与交互

- 工具栏固定为一行 `compact toolbar`，不再换成两行。
- 桌面端不换行；窄屏下允许横向滚动或局部压缩，但不恢复多行布局。
- 常驻高频操作：
  - 撤销
  - 重做
  - `H2`
  - `H3`
  - 加粗
  - 斜体
  - 无序列表
  - 引用
  - 代码块
  - “更多”
- 收纳到“更多”的低频操作：
  - 删除线
  - 有序列表
  - 链接
  - 表格
  - 分割线
  - 清空格式
- 工具按钮以图标优先、极短标签辅助的方式呈现，显著降低按钮高度和宽度。
- 激活态、hover、focus 继续保留，但视觉强度降低，不再像独立卡片块阵。
- “更多”采用下拉浮层，交互语言对齐 `StatusBar` 里的模式切换菜单，避免新增一套菜单样式。

### 3. 视觉样式与统一性

- 工具栏：
  - 从厚重分组卡片改为更薄、更平、更连续的一条控制带。
  - 保留现有玻璃感，但弱化阴影、分组包裹层和内部边框。
- 主编辑卡：
  - 继续作为页面主角。
  - 调整工具栏与主编辑卡之间的垂直节奏，让上方操作带和正文主卡之间更顺滑。
  - 标题区、正文区、卡片边界的比例会更克制，减少装饰性噪音。
- 发布设置：
  - 保留在页面下方。
  - 材质语言向主编辑卡靠拢，但降低对比度和装饰强度。
  - 作为附属设置区存在，而不是第二块主视觉区。
- 状态栏：
  - 继续固定底部。
  - 圆角、边框、背景混合和按钮密度与新工具栏统一。
  - 目标是和工具栏构成同一套控制系统，而不是独立漂浮操作台。
- 字体、间距、节奏：
  - 不更换站点字体体系，沿用当前基调。
  - `WritePage` 内部改为“主内容宽松，控制区紧凑”的节奏分配。
- 响应式：
  - 移动端优先保证正文可写、工具栏不换行、底栏可点、发布设置清晰。
  - 工具栏必要时支持横向滚动，由“更多”承担低频收纳。

## 结构与实现边界

### `src/components/post/EditorToolbar.vue`

- 重构工具栏 DOM，使其适配单行紧凑布局。
- 将低频按钮迁移到“更多”菜单中。
- 保留现有编辑行为，不改变命令触发逻辑本身。
- 新增菜单展开与关闭交互，并处理点击外部关闭。

### `src/views/Write.vue`

- 保持工具栏位于主编辑卡上方。
- 调整工具栏和主编辑卡之间的间距与容器宽度关系，让两者视觉上属于同一系统。
- 继续保留发布设置位于正文下方的结构。
- 如果需要，为工具栏的一行布局提供额外包裹层或溢出控制容器。

### `src/components/post/PublishPanel.vue`

- 下调卡片装饰强度，靠近主编辑卡体系。
- 统一与 write 页其余控制区的边框、背景和阴影语言。

### `src/components/post/StatusBar.vue`

- 统一与新工具栏的控件密度、圆角和材质语言。
- 不改变现有功能结构，只做视觉和节奏收敛。

### `src/assets/base.css`

- 复用现有 write 页 token。
- 只在必要时补充新的 write token，用于单行工具栏、更轻菜单和统一控制面板。
- 避免为本次优化引入过多一次性变量。

### `src/views/Write.test.ts`

- 先补充或改写结构性测试，锁定以下约束：
  - 工具栏仍位于主编辑卡上方。
  - 工具栏存在“更多”入口。
  - 主编辑卡结构继续存在。

## 非目标

- 不改变 write 页的核心编辑能力。
- 不新增封面、标签、草稿增强等功能性需求。
- 不把发布设置迁移到侧栏。
- 不重做整站导航或全局视觉系统。
- 不对 `WritePage` 之外的页面做大面积 UI 调整。

## 验证要求

- 先写失败测试，确认工具栏结构由“两行厚重按钮组”转向“单行常驻 + 更多收纳”的布局约束。
- 修改 `.vue` 文件后，运行 `npm test` 作为必需本地检查。
- 再运行完整回归：
  - `npm run lint`
  - `npm run test:run`
  - `npm run build`
- 进行浏览器视觉回归检查：
  - 桌面浅色模式
  - 桌面深色模式
  - 移动端浅色模式
  - 移动端深色模式
  - 工具栏是否保持一行
  - “更多”菜单是否可用
  - 标题区与正文区是否重新成为主视觉中心
  - 发布设置与状态栏是否已降噪并统一
